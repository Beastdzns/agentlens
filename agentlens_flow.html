AgentLens

AI Agent Observability Platform — traces every step an LLM agent takes, captures failures automatically, persists everything in SQLite, and serves it through a REST API + live dashboard.

FastAPI REST API Gemini 2.5 Flash Async Python SDK SQLite + aiosqlite WAL + Read Pool Auto Failure Capture Keyset Pagination
00 — Overview
What AgentLens Does

A complete stack for watching AI agents think — from SDK wrappers around every function call, all the way to a browsable web dashboard.

🔭

Full-Trace Observability

Every action the agent takes — planning, searching, tool calls, LLM calls — is recorded as a structured AgentEvent with timestamps, inputs, outputs, status, latency, and importance score.

💥

Automatic Failure Capture

SDK wrappers (capture_llm_call, capture_tool_call, capture_step) catch exceptions, persist a FAILURE event with exception_type + message, then re-raise. The trace survives even if the process crashes.

🗄️

SQLite Persistence

Phase 7 adds a full async SQLite backend — WAL journal mode, 1 write connection behind a lock, 4 read connections in a pool, automatic schema migrations, keyset pagination for traces.

🔄

Retry Linkage

When an agent retries a failed step the new event carries retry_of (pointer to the original failure) and an incremented attempt counter — building a full audit chain.

🌐

REST API + Dashboard

POST /api/run triggers the multi-step Gemini research agent. GET /api/traces lists with filters. The frontend dashboard replays every trace visually.

⚡

Dual Storage Backend

AGENTLENS_STORAGE=memory (default) keeps all tests green and fast. AGENTLENS_STORAGE=sqlite switches to the persistent SQLite backend for the live demo. Zero code change needed.

03 — Data Flow
How One Request Travels

Follow a single POST /api/run request from the browser all the way to the SQLite database and back.

🖱️

1. Browser / Client → POST /api/run

User hits "Run" in the dashboard (or calls the API directly). A JSON body like {"topic": "climate change"} is sent.

POST http://localhost:8000/api/run
Content-Type: application/json
{ "topic": "climate change" }
↓
⚙️

2. FastAPI Route Handler — web_api.py

Creates a new Trace, saves it to TraceStore, spawns the Gemini agent coroutine.

trace = create_trace(agent_id="research-agent")
await trace_store.save_trace(trace)
↓
🤖

3. Multi-Step Gemini Agent — collector.py

Runs 6 sequential phases. Each phase is wrapped by an SDK context manager that starts a timer, calls Gemini, and records the result.

async with collector.traced(agent_id, trace_id):
  async with collector.capture_llm_call("planning"):
    result = await gemini.generate(prompt)
↓
💥

4. Failure Capture (if exception)

If Gemini throws, the context manager catches it, writes a FAILURE event with exception_type, traceback_summary, then re-raises. The trace record stays intact.

# automatically inside capture_llm_call()
except Exception as e:
  await store.save_event(AgentEvent(status=FAILURE, ...))
  raise
↓
🧩

5. Normalizer — dict → AgentEvent

sdk_collector/normalizer.py converts the raw Gemini response dict into a validated AgentEvent Pydantic model with correct types, UUIDs, and timestamps.

event = AgentEvent.model_validate({
  "event_type": "llm_call",
  "latency_ms": elapsed_ms, "status": "success"
})
↓
🗃️

6. Storage Layer — save to backend

EventStore.save_event(event) called. If AGENTLENS_STORAGE=sqlite: JSON-encodes JSON fields, formats datetime as UTC ISO-8601, runs INSERT OR REPLACE INTO events. If memory: just stores in dict.

# sqlite.py
await db.execute_write("INSERT OR REPLACE INTO events ...", row)
↓
🗄️

7. SQLite — WAL write committed

Write connection (1, behind asyncio.Lock) appends to the WAL file. commit() atomically moves it to the main DB file. Concurrent reads from the 4-connection pool are never blocked.

agentlens.db-wal ← write goes here first
agentlens.db ← checkpoint merges WAL → main DB
↑ response
📡

8. API returns Trace JSON to browser

The route handler calls trace_store.get_trace(id) (read pool), serialises to JSON, returns 200. The dashboard polls /api/traces and renders the event timeline.

{ "trace_id": "...", "status": "success",
  "event_count": 6, "total_latency_ms": 3421 }
04 — Database Layer (Phase 7)
SQLite Backend — How It Works

The new storage/db.py + storage/sqlite.py — every design decision explained.

🔐 Write Connection

One single aiosqlite connection shared across all writes. An asyncio.Lock ensures only one coroutine writes at a time — no SQLite BUSY errors.

connections1 (write only)
concurrencyasyncio.Lock
commitafter every write / bulk op
executemanysingle transaction for bulk

📖 Read Pool

4 independent connections in an asyncio.Queue. Any coroutine that needs to read checks one out, uses it, puts it back — reads never block writes thanks to WAL.

pool sizeN = 4
mechanismasyncio.Queue
WAL benefitreads never blocked by writes

⚙️ PRAGMA Config

Applied to every connection (read and write) when it is first opened.

journal_modeWAL
synchronousNORMAL
busy_timeout5000 ms
foreign_keysON

📦 Migration Runner

On startup, scans migrations/*.sql sorted by filename. Applies unapplied ones in order. Records each in schema_migrations(version, applied_at). Idempotent — safe to restart.

applied file0001_initial.sql ✓
tracking tableschema_migrations
each migrationone transaction

📄 Keyset Pagination

list_trace_page() uses row-value comparison for stable, fast pages — no OFFSET scan even with millions of traces. Cursor is base64-encoded "start_time|trace_id".

SQLWHERE (start_time, trace_id) < (?, ?)
orderstart_time DESC, trace_id DESC
cursorbase64("st|tid")
default page20 traces

🔀 Dual Backend

Switching storage is one env var. Both backends implement the exact same abstract interface so routes and collector code never know which is active.

AGENTLENS_STORAGE=memoryInMemory (default)
AGENTLENS_STORAGE=sqliteSQLite backend
run_demo.pyopts into sqlite
pytestalways memory → fast

06 — Configuration
Environment Variables

Copy .env.example to .env and fill in your values. All variables are optional — defaults shown below.

VariableDefaultDescription
GEMINI_API_KEY — Your Google Gemini API key. Required for the live research agent. Without it the agent runs in offline-fallback simulation mode.
GEMINI_MODEL gemini-2.5-flash Gemini model to use. Can be changed to any available model ID.
AGENTLENS_STORAGE memory Storage backend. memory = fast in-memory (all tests). sqlite = persistent SQLite (run_demo.py). Default keeps all pytest tests green.
AGENTLENS_DB_PATH ./agentlens.db Path to the SQLite file. Only used when AGENTLENS_STORAGE=sqlite. Will be created automatically on first run.
PORT 8000 TCP port for the FastAPI / Uvicorn server. Auto-increments if the port is already in use.
CORS_ORIGINS * Allowed CORS origins for the REST API. Set to your frontend URL in production.
07 — Testing
How to Run Everything

Run these commands from the agentlens/ directory.

Install / update dependencies
pip install -e ".[dev]"
Installs the package in editable mode + all dev dependencies including aiosqlite, pytest, pytest-asyncio.
Run storage unit tests (29 tests — should always be green)
python -m pytest tests/test_storage.py -v
Uses the in-memory backend. No env vars needed. Should show 29 passed in <1 second.
Run the SQLite smoke test (new in Phase 7)
python tests/smoke_sqlite.py
Creates a temp SQLite DB, applies migrations, tests event round-trip, ordering, bulk-save, trace CRUD, count_traces, and keyset pagination. Should print 6 [OK] lines.
Run all tests
python -m pytest -v --tb=short
Runs the full test suite. All existing tests use memory backend so they stay fast and green.
Run the live demo (uses SQLite)
python run_demo.py
Starts Uvicorn on port 8000, opens the dashboard at http://127.0.0.1:8000/app/, uses SQLite persistence. Database file: ./agentlens.db
Run demo on a specific port
python run_demo.py --port 9000 --no-browser
Run without auto-opening the browser. Useful for server/headless environments.
Check the SQLite database directly
python -c "import sqlite3, pprint; db=sqlite3.connect('agentlens.db'); pprint.pprint(db.execute('SELECT trace_id,agent_id,status,event_count FROM traces LIMIT 5').fetchall())"
Quick sanity check — list the 5 most recent traces directly from SQLite (after running the demo).
Commit Phase 7 to your branch
git commit -m "feat(storage): async SQLite backend, migrations, keyset pagination, memory parity"
All Phase 7 files are already staged (git add was done). This is the final commit command.
