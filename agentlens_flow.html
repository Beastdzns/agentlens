01 — Overview
What is AgentLens?

An observability SDK + REST API that automatically instruments AI agents — capturing every LLM call, tool invocation, and failure — so you can debug and replay any run.

🔭

Full-Trace Observability

Every action the agent takes — planning, searching, retrieving, synthesizing — is recorded as a structured AgentEvent with timing, inputs, outputs, and status.

💥

Automatic Failure Capture

New SDK wrappers (capture_llm_call, capture_tool_call, capture_step) detect exceptions, persist a FAILURE event with exception_type + message, then re-raise — so the trace survives even if the process dies.

🔄

Retry Linkage

When an agent retries a failed step, the new event carries retry_of (pointer to the original failure) and an incremented attempt counter — building an audit chain.

🌐

REST API

POST /api/run triggers the multi-step research agent. GET /api/traces/{id} retrieves any trace with filtering by status or event type.

⚡

Async-Safe SDK

All context (trace ID, parent ID, agent ID) lives in contextvars — so concurrent agents each maintain isolated traces without any locks.

🧪

172 Tests Passing

Comprehensive test suite covering unit, integration, and HTTP-layer tests. 18 new tests added specifically for the automatic failure capture feature.

04 — New SDK Helpers
Automatic Failure Capture Wrappers

Three async context managers added to EventCollector. Each one times the operation, records the right event type, and — on exception — captures exception_type + exception_message before re-raising.

capture_llm_call()

Wraps a Gemini (or any LLM) call. Yields a result[0] list to populate with the response.
⏱️
Start timer · set up result = [""]
▼
🤖
Body runs — call Gemini, assign result[0] = response
▼        ↓ (on exception)
✅
Record LLM_CALL / SUCCESS
prompt + response in event
❌
Record LLM_CALL / FAILURE
exception_type + message → re-raise
async with collector.capture_llm_call(
  prompt="Synthesize findings",
  model="gemini-2.5-flash",
  metadata={"step": "synthesis"},
  retry_of=failed_id, # optional
  attempt=2, # optional
) as result:
  result[0] = await call_gemini(prompt)
answer = result[0]

capture_tool_call()

Wraps any tool invocation (web search, DB query, etc.). Yields a result[0] list to populate with the output dict.
⏱️
Start timer · set up result = [None]
▼
🔧
Body runs — call tool, assign result[0] = {"hits": [...]}
▼        ↓ (on exception)
✅
Record TOOL_CALL / SUCCESS
input + output in event
❌
Record TOOL_CALL / FAILURE
exception_type + message → re-raise
async with collector.capture_tool_call(
  "web_search",
  input_data={"query": q},
  metadata={"step": "search"},
) as result:
  result[0] = await web_search(q)
hits = result[0]

capture_step()

Generic wrapper for any pipeline step that doesn't return a value (retrieval, memory-write, final-response bookend).
⏱️
Start timer · note event_type
▼
⚙️
Body runs — any arbitrary async work
▼        ↓ (on exception)
✅
Record EventType / SUCCESS
+ latency_ms
❌
Record EventType / FAILURE
exception_type + message → re-raise
async with collector.capture_step(
  EventType.RETRIEVAL,
  input_data={"top_k": 3},
  metadata={"step": "retrieval"},
  retry_of=failed_id, # optional
  attempt=2,
):
  pass # or real work here
05 — Retry Linkage
Tracing Retry Chains

When a step fails and is retried, the new event's metadata carries retry_of (UUID of the failed event) and an incremented attempt counter — letting you reconstruct the full retry chain from the trace.

❌ Attempt 1 — FAILURE
LLM_CALL / synthesis
event_id: a1b2c3d4…
metadata.exception_type: "RuntimeError"
metadata.exception_message: "Gemini quota exceeded"
↓
retry_of = "a1b2c3d4…"  ·  attempt = 2
🔄 Attempt 2 — FAILURE
LLM_CALL / synthesis (retry)
event_id: e5f6a7b8…
metadata.retry_of: "a1b2c3d4…" (→ attempt 1)
metadata.attempt: 2
metadata.exception_type: "TimeoutError"
↓
retry_of = "e5f6a7b8…"  ·  attempt = 3
✅ Attempt 3 — SUCCESS
LLM_CALL / synthesis (retry)
event_id: c9d0e1f2…
metadata.retry_of: "e5f6a7b8…" (→ attempt 2)
metadata.attempt: 3
output_data.response: "The evidence suggests…"
06 — Acceptance Criteria
All Criteria Met ✅

The four requirements from the task — verified by 18 new tests.

  • ✅

    Reusable SDK wrappers added

    capture_llm_call(), capture_tool_call(), and capture_step() added to EventCollector in sdk_collector/collector.py. Each times execution, records SUCCESS on clean exit, and records FAILURE with exception_type + exception_message on error before re-raising.

  • ✅

    _AgentRunner.run() refactored — per-step capture

    All 6 pipeline steps (planning, search, retrieval, memory-write, synthesis, final-response) are now routed through the per-step wrappers. The single coarse try/except was replaced — each step has its own capture context manager.

  • ✅

    Retry linkage

    All three wrappers accept retry_of: Optional[UUID] and attempt: int. When provided, both are serialized into the recorded event's metadata dict — linking the retry to its predecessor regardless of whether the retry succeeded or failed.

  • ✅

    Acceptance test: killing Gemini mid-run persists exactly 1 FAILURE event

    Verified by TestPipelineFailureCapture::test_gemini_failure_persists_failure_trace: when Gemini raises during synthesis, the stored trace contains exactly one FAILURE event of type LLM_CALL with exception_type = "RuntimeError" and exception_message = "Gemini quota exceeded".
